# 落とし穴集

Minecraft Bedrock をコマンド／MCP 経由で建築したときに実際に踏んだ問題と、その回避策。
すべて実機で確認したもので、推測は含めない。

## 建築

### hollow で建てても内部は掃除されない

`build_cube` の `hollow: true` は**外殻を置くだけ**で、内部にある既存ブロックには触れない。
木の中や草地に建てると、室内に葉・草・花が残る。実測で 9x9 の小屋に 31 ブロックの
残留物があった。

**対策**: 建築範囲全体を `air` で `fill` してから外殻を建てる。順序が逆だと意味がない。

### fill の outline を単層に使うと全面が埋まる

外周だけを縁取るつもりで `mode: outline` を高さ 1 の範囲に適用すると、9x9 = 81 ブロック
全部が埋まる。`outline` は「中空の箱の外殻」を作るモードなので、厚みがない層では
全体が外殻と判定される。

**対策**: 枠を作りたいときは四辺を個別に `fill` する。`outline` は立体にだけ使う。

### 地面との段差が 2 以上あると入れない

プレイヤーがジャンプで登れるのは 1 ブロックまで。斜面に建てると、低い側から入口に
たどり着けなくなる。

**対策**: 入口の外に 1 ブロックずつ上がる踏み段を置く。段数は設置場所の地形に依存するので、
ブループリントに固定で書くと平坦地では宙に浮く（既知の課題）。

### 斜面には keep モードの基礎を使う

`fill` の `mode: keep` は**空気の部分だけ**を埋める。床下の空隙を埋めて建物が浮くのを
防ぎつつ、既存の地面を削らずに済む。`replace` にすると地形を破壊する。

## ブロック ID

### オークのドアは `oak_door` ではなく `wooden_door`

他の木材は `spruce_door` / `birch_door` / `dark_oak_door` のように `<木材>_door` だが、
**オークだけ例外**で `wooden_door`。`oak_door` を指定すると
`構文エラー: "oak_door" は無効です` になる。

生コマンドではブロック名に `minecraft:` を付けない。

### ドアの上半分を自分で置いてはいけない

`setblock` で下半分を置けば**上半分は自動生成される**。
`["upper_block_bit"=true]` を明示して上半分を置こうとすると
`statusCode: -2147352576` で失敗する。

ドアを 2 枚横に並べると両開き扉として機能する。

## 読み取り

### get_top_solid_block の y は「探索の開始高度」

地表を知るツールに見えるが、実体は `/gettopsolidblock` で、**指定座標から下方向に**
最初の固体ブロックを探す。`y` を渡すとその高度から下だけを見るので、プレイヤーの
足元に洞窟があると「地表」ではなく空洞の底が返る。

**対策**: 地表を知りたいときは `y` を省略する（既定で 320 が使われ、上空から探すので
本当の地表が返る）。

### 応答メッセージの y は常に `none`

`Top solid block found at (-194, none, -556)` と表示されるが、これは実装が
`result.y` を読んでいるためで、実際の値は `result.location.y` にある。
**データ本体は正しい**ので、メッセージだけ見て「取得に失敗した」と誤解しないこと。

## 接続（minecraft-claude 側）

### Minecraft の画面表示は接続状態の証拠にならない

- WebSocket が切れても Minecraft は明示的に知らせないことがある
- 逆に「何も表示されない」のに接続は成立していることもある

どちらも実際に遭遇した。**判断は必ずサーバ側で行う**（`ss -tln | grep 8001` と
`logs/server.log`）。ワールド内に Agent が見えていても接続とは無関係。

### マルチプレイでは socket-be のクラッシュ対策が必須

未対策の socket-be はマルチプレイサーバへの接続直後にプロセスごと落ちる。
詳細と対策は `minecraft-claude` の README を参照。
