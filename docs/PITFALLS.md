# 落とし穴集

Minecraft Bedrock をコマンド／MCP 経由で建築したときに実際に踏んだ問題と、その回避策。
すべて実機で確認したもので、推測は含めない。

## 建築

### hollow で建てても内部は掃除されない

`build_cube` の `hollow: true` は**外殻を置くだけ**で、内部にある既存ブロックには触れない。
木の中や草地に建てると、室内に葉・草・花が残る。実測で 9x9 の小屋に 31 ブロックの
残留物があった。

**対策**: 建築範囲全体を `air` で `fill` してから外殻を建てる。順序が逆だと意味がない。

### fill の outline を単層に使うと全面が埋まる

外周だけを縁取るつもりで `mode: outline` を高さ 1 の範囲に適用すると、9x9 = 81 ブロック
全部が埋まる。`outline` は「中空の箱の外殻」を作るモードなので、厚みがない層では
全体が外殻と判定される。

**対策**: 枠を作りたいときは四辺を個別に `fill` する。`outline` は立体にだけ使う。

### 階段の最下段を壁に接して置かない

最下段が壁に接していると、正面から乗れず横から回り込むことになる。
**最下段の手前に 1 マスの踏み込みスペース**を残すこと。

階段の向きは「どこに置けるか」だけでなく「最下段の手前に立てるか」で決める。
北壁沿いに南向きの階段を架けて実際にこれを踏んだ。東向きに変えたら解決した。

### 階段を動かしたら、その階の家具も見直す

階段の位置を変えると吹抜も動く。**家具の座標を見直さないと、床のない吹抜の上に
家具が浮く**。ベッドを吹抜の真上に置いてしまい、さらに別の 1 台が階段の着地点を
塞いでいた。

階段ブロックとの座標衝突だけを見て「干渉なし」と判断するのは誤り。
確認すべきは 3 つある。

1. 階段ブロックそのものと重なっていないか
2. **吹抜（床を抜いた範囲）の上に乗っていないか**
3. **階段を上りきった着地点を塞いでいないか**

`testforblock <x> <y> <z> air` で 1 マスずつ確かめられる。

そして **見直しは全フロアぶん行う**。3 階のベッドだけ直して 2 階のキッチンを
放置し、同じ指摘を二度受けた。階段は複数階を貫くので、影響も全階に及ぶ。

### 地面との段差が 2 以上あると入れない

プレイヤーがジャンプで登れるのは 1 ブロックまで。斜面に建てると、低い側から入口に
たどり着けなくなる。

**対策**: 入口の外に 1 ブロックずつ上がる踏み段を置く。段数は設置場所の地形に依存するので、
ブループリントに固定で書くと平坦地では宙に浮く（既知の課題）。

### 斜面には keep モードの基礎を使う

`fill` の `mode: keep` は**空気の部分だけ**を埋める。床下の空隙を埋めて建物が浮くのを
防ぎつつ、既存の地面を削らずに済む。`replace` にすると地形を破壊する。

## ブロック ID

### オークのドアは `oak_door` ではなく `wooden_door`

他の木材は `spruce_door` / `birch_door` / `dark_oak_door` のように `<木材>_door` だが、
**オークだけ例外**で `wooden_door`。`oak_door` を指定すると
`構文エラー: "oak_door" は無効です` になる。

生コマンドではブロック名に `minecraft:` を付けない。

### ドアの上半分を自分で置いてはいけない

`setblock` で下半分を置けば**上半分は自動生成される**。
`["upper_block_bit"=true]` を明示して上半分を置こうとすると
`statusCode: -2147352576` で失敗する。

これは構文の問題ではなく、**上半分を単独で置く操作自体が無効**なため。
状態指定そのものは有効に働く（後述）。

### 両開きドアはヒンジを反転させる

ドアを 2 枚並べただけでは、**両方が同じ向きに開いて**観音開きにならない。
片方だけ `["door_hinge_bit"=true]` を指定し、ヒンジを反対側に置く。

## ブロック状態の指定

`setblock` にブロック状態を渡せる。**ブロック名との間にスペースを空ける**。

```
setblock 32 66 -254 wooden_door ["door_hinge_bit"=true]
setblock 33 65 -255 oak_stairs ["weirdo_direction"=1,"upside_down_bit"=false]
```

MCP の `blocks set_block` はブロック ID しか受け取れないので、状態が必要なブロックは
`world run_command` の生コマンドを使う。ブループリントでは `state:` を書けば
自動的に生コマンド経路になる。

### 階段の向き（weirdo_direction）

`weirdo_direction` は 0〜3 で階段の向きを表す。名前から方角は読み取れないが、
4 方向すべてを実機で確認した結果は以下のとおり。

| 値 | 高い側（背もたれ）が向く方角 |
| --- | --- |
| 0 | 東 (+X) |
| 1 | 西 (−X) |
| 2 | 南 (+Z) |
| 3 | 北 (−Z) |

つまり **「高い側が向く方角」** で読む。東から登る階段（＝高い側が西）は 1 で、
0 では逆を向く。椅子として使うときは、背もたれを外側に向ける値を選ぶ。

### 吊り下げランタンは hanging を指定する

`lantern` をそのまま置くと床置きの形になる。天井や鎖から吊るすには
`["hanging"=true]` が要る。`chain` を上に重ねると吊り下げ照明になる。

### アドオン家具の向きはバニラ階段と逆

Another Furniture Add-On (`sf_afm:`) の家具は `minecraft:cardinal_direction` で
向きを指定するが、**指定するのは「背面が向く方向」**。座らせたい向きの反対を書く。

```
setblock <x> <y> <z> sf_afm:chair_0.block ["minecraft:cardinal_direction"="west"]
  → 椅子は EAST を向く（背もたれが西）
```

バニラ階段の `weirdo_direction` は「高い側（背もたれ）が向く方角」なので**同じ考え方**
だが、値の書き方が違う（数値 0-3 と方角名）ため取り違えやすい。並べて置くときは
必ず実機で確認すること。既定値は `south`（＝北を向いて座る）。

なお `direction` `facing_direction` は「そのブロックでは無効です」と明示的に
エラーになるので、状態名の切り分けは早い。

### 囲いを上げたら中身の高さも上げる

浴槽の縁を 1 段立ち上げたのに水位を据え置いたため、水面が床と同じ高さになり
「水が入っていない」ように見えた。`testforblock` では水は存在していた。

**見た目の不具合は、ブロックの有無ではなく高さの不一致であることがある。**
「無い」と判断する前に `testforblock` で実在を確かめる。

### カーペットは色ごとに別の ID

`red_carpet` `white_carpet` のように色名込みの ID を使う。
床の装飾は**家具より先に敷く**こと。後から fill するとテーブルや椅子を上書きする。

## 読み取り

### get_top_solid_block の y は「探索の開始高度」

地表を知るツールに見えるが、実体は `/gettopsolidblock` で、**指定座標から下方向に**
最初の固体ブロックを探す。`y` を渡すとその高度から下だけを見るので、プレイヤーの
足元に洞窟があると「地表」ではなく空洞の底が返る。

**対策**: 地表を知りたいときは `y` を省略する（既定で 320 が使われ、上空から探すので
本当の地表が返る）。

### 応答メッセージの y は常に `none`

`Top solid block found at (-194, none, -556)` と表示されるが、これは実装が
`result.y` を読んでいるためで、実際の値は `result.location.y` にある。
**データ本体は正しい**ので、メッセージだけ見て「取得に失敗した」と誤解しないこと。

## 接続（minecraft-claude 側）

### Minecraft の画面表示は接続状態の証拠にならない

- WebSocket が切れても Minecraft は明示的に知らせないことがある
- 逆に「何も表示されない」のに接続は成立していることもある

どちらも実際に遭遇した。**判断は必ずサーバ側で行う**（`ss -tln | grep 8001` と
`logs/server.log`）。ワールド内に Agent が見えていても接続とは無関係。

### マルチプレイでは socket-be のクラッシュ対策が必須

未対策の socket-be はマルチプレイサーバへの接続直後にプロセスごと落ちる。
詳細と対策は `minecraft-claude` の README を参照。
